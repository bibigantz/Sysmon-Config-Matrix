# Sysmon Config Matrix & Multi-Manager

Import, compare, batch-edit, validate, and export Sysmon configuration files across multiple
isolated network environments (Corporate, OT/SCADA, Cloud, DMZ, air-gapped labs, ...) from one
dark-themed SOC-style dashboard.

<br clear="left" />

## Running it — works offline, out of the box

**This folder is a ready-to-run, self-contained build**: `./vendor/` already has every dependency
vendored (see **Air-gapped / offline mode** below), and `index.html` defaults to using it, so you
can copy this entire folder to any machine — including one with zero internet access — and it just
works. No Node.js, no `npm install`, no setup step required.

**This machine does not have Node.js installed** anyway, so the app is built with **zero build
step**: every dependency (React, Zustand, fast-xml-parser, lucide-react, JSZip) loads as a
pinned-version ES module via a browser **import map** when the page opens — see
`requirements/dependencies.json`. That import map defaults to the local `./vendor/` copies; see
**Air-gapped / offline mode** below for how to switch to the esm.sh CDN instead on a machine that
does have internet (e.g. to pick up a dependency update).

You still need to serve the folder over `http://`, not open `index.html` directly via
`file://`, because the browser's `fetch()` (used to load the bundled sample configs from
`requirements/examples/`) is blocked for local files by browser security policy. Any static
file server works:

```bash
# Option A - Python (already installed on this machine, no Node required)
cd sysmon-config-manager
python -m http.server 5173
# then open http://localhost:5173

# Option B - if Node.js is ever installed on this machine
npx serve .
```

If you later get Node.js on this machine and want a real bundled TypeScript build (Vite,
production minification, etc.), `package.json` already lists the npm equivalents of every CDN
dependency — `src/` already imports bare package names (`'react'`, `'zustand'`, ...), so a bundler
can resolve them directly once you `npm install`; just drop the import-map bootstrap in
`index.html` since a bundler replaces that role.

## Air-gapped / offline mode (the default)

`src/` never hardcodes a CDN URL - every file imports a bare specifier (`'react'`, `'jszip'`, ...)
and a small inline script in `index.html` decides, before any module loads, whether those
resolve to a local `./vendor/` folder or to esm.sh, via a browser **import map**. **This folder
already ships with `./vendor/` populated and defaults to using it** - no setup, no toggle to
click, no internet access needed the first time you open it. A visible badge in the top bar (or
`?modules=vendor` / `?modules=cdn` in the URL) switches modes and reloads if you ever want esm.sh
instead (e.g. on a machine with internet, to pick up a newer dependency version); the choice is
remembered per browser in `localStorage`.

Ship the whole `sysmon-config-manager/` folder (including `vendor/`, `favicon.svg`, and the other
icon files at the project root) to the air-gapped network and serve it with any static file server
- no CDN access, no Node.js, and no further internet access is required. This was verified by
actually blocking every non-localhost network request in a real browser (fresh profile, no prior
`localStorage`) and confirming the app loads and every tab works fully (see
`requirements/schema-notes.md` for what that test covered).

If a dependency version ever changes, regenerate `./vendor/` once while online:

```bash
cd sysmon-config-manager
python requirements/vendor-deps.py
```

This downloads React, ReactDOM, Zustand, fast-xml-parser, lucide-react, htm, JSZip, their
transitive dependencies, and the Tailwind CDN script into `./vendor/`, rewriting every internal
import to a local relative path so nothing inside `vendor/` still reaches out to esm.sh.

## Feature tour

- **Help & Documentation** — the `?` button in the top bar opens an in-app Help Center
  (`src/components/HelpCenter.js`): a searchable left-nav of topics (Getting Started, Matrix View,
  Rule Management, Merge & Policy Builder, Sigma-to-Sysmon Auditor, Risk Analyzer & Sanitizer,
  Export & Air-Gapped Deployment, a Sysmon quick reference generated live from `eventSchema.js` so
  it can't drift from the real dropdowns, Local AI & LLM Assistant, and an FAQ accordion), with
  copyable syntax-highlighted code snippets and info/warning/best-practice callouts. Content lives
  in `src/content/helpTopics.js`; shared pieces (callouts, code blocks, accordion, the Developer
  Mode box) are in `src/components/HelpPrimitives.js`.
  - **Developer Mode** - a toggle in the Help Center's header (persisted via
    `src/store/useHelpDevStore.js`) reveals purple "Developer Mode" boxes throughout every topic,
    each naming the exact file/function that runs for the action just described - e.g. which store
    action, which `utils/*.js` function, and whether an LLM is involved anywhere (it almost never
    is - see the AI Assistant topic for the one place it is). Off by default; changes nothing about
    how the app itself behaves, only what this Help window shows.
  - **EN / עברית toggle** - an `EN`/`עברית` switch in the Help Center's header swaps the entire
    help page to a complete, pre-written Hebrew translation (`src/content/helpTopics.he.js`) -
    translated once, offline, ahead of time, so the toggle is just a static language swap with no
    translation service involved. Switching also flips the content pane to `dir="rtl"` (mirroring
    the nav to the right automatically via flexbox); literal code/tag/attribute mentions
    (`<ProcessCreate>`, `onmatch`, `contains`, ...) are deliberately left untranslated in both
    languages since they're syntax the user must type verbatim, not prose. The choice persists to
    `localStorage` and the currently open topic stays selected across the switch (both language
    arrays share the same topic ids). Developer Mode content is English-only (not yet translated).
- **Per-page intro banners** — every tab opens with a short, always-visible description of what
  that page does (`PageIntro` in `src/components/ui.js`), distinct from the full Help Center
  documentation - a quick "what am I looking at" before you dive in.
- **⚙ Settings menu** (top bar, right side) — consolidates the Local AI status/config link,
  offline-vendor/CDN module source toggle, Light/Dark/System theme toggle, and the Help button into
  one dropdown (`src/components/SettingsMenu.js`) so the tab strip itself stays uncluttered as
  features are added; the tab strip scrolls horizontally on its own if it ever has more tabs than
  fit a given window width, so this menu's trigger button is never pushed off-screen.
- **Light / Dark / System theme** — a 3-way toggle in the top bar (Sun / Monitor / Moon)
  switches instantly via Tailwind `dark:` variants (`darkMode: 'class'`); the choice persists to
  `localStorage` and "System" tracks `prefers-color-scheme` live, including while the app is open.
  State lives in `src/store/useThemeStore.js`; a tiny inline script in `index.html` applies the
  class synchronously before first paint to avoid a flash of the wrong theme. The Raw Editor's XML
  syntax highlighting (`src/utils/xmlHighlight.js`) and every diff/risk color use the same
  `dark:`-paired palette, so nothing goes unstyled or low-contrast when switching.
- **Dashboard** — per-network summary cards: schema version, hash algorithms, rule counts by
  event type, and inline validation issues (errors/warnings/info).
- **Matrix View** — every Sysmon Event ID as a row, every network as a column, with
  include/exclude counts per cell. Filter by Event ID, onmatch, GroupRelation, MITRE technique, or
  free-text keyword across field values; click a row to expand full per-network rule detail,
  including an **inline edit** (pencil icon) to fix a rule's onmatch, add/remove/change individual
  filter conditions, or update its comment directly - no need to delete and recreate a rule via
  the Injector just to fix one value - plus suppress/re-enable and delete.
- **Side-by-Side Diff** — pick any two networks; rules are bucketed by event tag + onmatch and
  classified as added / removed / modified (same field+condition, different value) / unchanged.
- **Global Rule Injector** — build a rule via dropdowns (Event ID/tag, include/exclude, field,
  condition, value) or paste a raw XML snippet; preview conflict/duplicate detection against every
  selected target network before applying; apply to all or a checked subset of networks.
- **Merge & Policy Builder** (`Merge & Combine` tab) — see the dedicated section below: four
  deterministic, code-only merge modes (Union, Intersection, Differential, Hierarchical
  Inheritance) across any selected networks, with an interactive conflict-resolution panel, a
  redundancy/overlap heuristic, and a live XML preview you can save back into the workspace or
  export.
- **Sigma-to-Sysmon Auditor** (`Sigma Auditor` tab, `src/components/SigmaAuditor.js`) — paste,
  import (`.yml`/`.yaml`), or write a Sigma detection rule in a live, syntax-highlighted YAML
  editor (own hand-rolled parser, `src/utils/yamlLite.js` - no external YAML library) with on-the-fly
  validation; **Run Sysmon Audit** translates the rule's `logsource`/`detection` block
  (`src/utils/sigmaToSysmon.js` + `sigmaMapping.js`, including `and`/`or`/`not` and `1 of x*`
  condition grammars) into candidate Sysmon filters and checks every loaded network for coverage
  (`src/utils/sigmaAudit.js`) - 🟢 Covered, 🔴 Gap Detected, or Unmappable (non-Sysmon logsource).
  For any gap, **Preview Patch** shows a side-by-side original-vs-proposed XML diff
  (`src/utils/lineDiff.js`, a hand-rolled LCS line diff) with the exact rule(s) to be inserted;
  nothing is written until you click **Confirm & Update Config** - per network, or in batch via
  **Approve & Inject All Gaps**. Injected rules show up everywhere else in the app (Matrix View,
  Diff, Export) exactly like a rule added through the Global Rule Injector, including Undo/Redo.
  Coverage matching is a field/condition/substring heuristic, not a Sysmon execution engine -
  flagged clearly in the UI, same honesty standard as the Risk Analyzer below.
- **Global Rule Remover / Suppressor** (sidebar button) — search for rules across chosen networks
  by keyword/field/Event ID, or by pasting a raw XML snippet to match on exact filter content, then
  either delete the matches outright or suppress them (comment them out in the exported XML while
  keeping the rule, greyed out and re-enablable, in the app).
  - Suppressed rules stay visible everywhere in the UI (Matrix View, Dashboard counts exclude them
    from "active" inc/exc tallies but show an "N off" badge) so nothing silently disappears.
- **Sanitize & Standardize Casing** (Raw Editor/Export toolbar, or "Sanitize All Networks" in the
  sidebar) — rewrites tag/attribute/condition casing to the official Sysmon schema casing (parsing
  itself is already tolerant of mis-cased input so nothing is lost on import; this is the explicit
  cleanup step for producing schema-correct output).
- **Loose / orphaned rule handling** — a filter condition with no enclosing event tag, a
  non-standard `<Include>`/`<Exclude>` wrapper, or a well-formed event tag found outside
  `<EventFiltering>` entirely are never dropped: the parser auto-wraps them into a synthesized
  rule (best-guess event tag, inferred from which known tag documents the fields involved) and
  flags it `orphaned: true`. Flagged rules show an amber "Loose Rule / Unwrapped" badge in Matrix
  View, the Diff Viewer, and the Global Rule Remover's results, plus a dedicated **"Show Loose /
  Unwrapped Rules Only"** checkbox in Matrix View and an aggregate risk-count pill. **"Wrap Loose
  Rules into RuleGroups"** (next to Sanitize, per-network or for all networks) is the explicit
  cleanup step that accepts the best-guess wrapping, names a `RuleGroup`, and clears the flag -
  see `requirements/schema-notes.md` for exactly how the event-tag guess is made and how exports
  stay valid either way.
- **Smart Condition & Wildcard Risk Analyzer** (Matrix View) — flags, per row: cross-network
  **operator mismatches** (the same target value excluded/included with `contains` in one network
  but `is`/`begin with` in another), **overly broad rules** (a short, non-path `contains`/`begin
  with`/`end with` match that risks log flooding or, for driver/image-load exclusions, dropping
  legitimate drivers), and **loose/orphaned rules** (see above).
- **Raw Editor / Export** — hand-edit a network's XML directly, re-validate and save back into the
  model; export one network or all of them as a `.zip`, in standard, SwiftOnSecurity-style, or
  Olaf Hartong modular-style formatting. Original comments (banner headers, inline notes, per-rule
  documentation) are preserved through edit/export, and suppressed rules re-export as inert,
  clearly-labeled XML comments rather than being silently dropped.
- **Undo / Redo** — sidebar buttons roll back/forward through imports, injected rules, deletions,
  suppressions, sanitize passes, and raw-XML edits for the current session.
- **MITRE ATT&CK tagging** — rules are auto-tagged with suggested technique IDs via keyword
  heuristics (`src/utils/mitreMap.js`); filter the Matrix View by technique.
- **Air-gapped / offline mode** — see the dedicated section above.
- **Local AI & LLM Assistant** — an optional, fully local AI layer (see **Local AI / LLM
  Assistant** below): connects to a locally/LAN-hosted Ollama or Open WebUI instance (never a
  cloud API) for Sysmon Config Matrix gap analysis, natural-language rule generation (with the
  same preview/conflict-check/inject flow as the Global Rule Injector), and per-rule explanation +
  MITRE mapping + false-positive-risk review. A live status badge and an **Open Local AI Config**
  link live in the ⚙ Settings menu (top bar); every other feature in the app works fully with the
  AI disconnected or never configured.

## Merge & Policy Builder

The **Merge & Combine** tab (`src/components/MergeWorkspace.js`, algorithms in
`src/utils/mergeEngine.js`) combines, intersects, diffs, or layers multiple loaded networks into
one output config - entirely with deterministic set operations and structural rule
regrouping/dedup on the same normalized `{ schemaversion, globals, rules }` model the rest of the
app uses. **No AI/LLM is involved anywhere in this feature.**

1. **Select input sources** in the left panel - check 2+ loaded networks (or drop/browse fresh
   `.xml` files right there to import and immediately make them selectable), then mark one as the
   **Base / Primary** (crown icon). The base is required for Hierarchical mode (its header/schema
   stay untouched), used as Source A for Differential mode, and used as the tiebreak default for
   schema/hash in Union and Intersection mode when there's no explicit conflict resolution.
2. **Pick a merge mode:**
   - **Union / Additive** — every unique rule across all sources, with identical condition lines
     (same field + condition + value within the same Event tag + onmatch) deduplicated.
   - **Intersection** — only condition lines present, identically, in *every* selected source - a
     mandatory shared baseline.
   - **Differential / Override** — condition lines in the base (Source A) that are missing from
     the other selected source (Source B); swap which one is "A" with the Crown button or the
     Swap A↔B shortcut to flip direction.
   - **Hierarchical Inheritance** — the base network's header, `schemaversion`, and
     `HashAlgorithms`/other globals pass through completely untouched; overlay networks only ever
     ADD condition lines the base doesn't already have. The base's own rules are carried through
     unmodified (not re-deduplicated or reformatted).
3. Click **Run Merge**. The **Conflict Resolution** panel then surfaces anything that needs a
   human decision - resolving one never corrupts the others, since every choice is replayed from
   scratch against the original merge output rather than mutated in place:
   - **Onmatch conflicts** (e.g. one source excludes `mimikatz.exe`, another includes it under the
     same Event tag) — *Keep Source A*, *Keep Source B*, *Keep Both (Separate Rules)*, or *Merge
     into RuleGroup (OR)* (tags both sides with a shared `groupRelation="or"` RuleGroup name).
   - **GroupRelation mismatches** (`and` vs `or` for the same RuleGroup/Event tag across sources) —
     pick which value wins.
   - **HashAlgorithms / schema version mismatches** — a dropdown of every value seen, across
     every source, to pick the one unified value for the output.
   - A separate **Redundancy / Overlap Check** panel flags (never auto-removes) a narrower
     `contains`/`begin with` condition whose value is already covered by a broader one on the same
     field (e.g. `begin with "C:\Windows\Temp\sub"` once `contains "C:\Windows\Temp"` exists) -
     "Remove narrower line" is a deliberate, one-click, reversible-via-Undo-after-save action.
4. Every merged condition line is commented with its **source attribution** (e.g. "Merged from
   ConfigOT.xml, ConfigCorp.xml" or "Only in ConfigOT.xml (not present in ConfigCorp.xml)") -
   preserved through to export, same as any other rule comment.
5. The **live preview** pane re-serializes on every change (any style - Standard /
   SwiftOnSecurity / Olaf Hartong) and shows the same validation badge used in Raw Editor/Export.
   **Save as new workspace network** feeds the merged XML back through the normal import/parse
   pipeline (so it's re-validated exactly like any uploaded file) and adds it as a new network in
   the sidebar; **Download** exports `ConfigMerged.xml` directly.

## Local AI / LLM Assistant (air-gapped friendly)

**Local AI Config** (opened from the ⚙ Settings menu in the top bar, not a tab of its own)
connects this app to a locally or LAN-hosted LLM server — never a cloud API
(OpenAI/Anthropic/Google are never contacted; see `src/utils/aiClient.js`, which only ever
fetches the base URL you type in). Two local server shapes are supported, auto-detected by
default:

- **Ollama native** — `http://localhost:11434` (uses `/api/tags` to list models, `/api/chat` to
  generate).
- **OpenAI-compatible** — e.g. Open WebUI's `http://localhost:8080/api`, or LM Studio / llama.cpp
  server (uses `/v1/models` or `/models` to list models, `/chat/completions` or
  `/v1/chat/completions` to generate), with an optional bearer token field for servers that
  require auth.

### Setup

1. Install and run a local LLM server on this workstation or an internal/air-gapped LAN server —
   e.g. [Ollama](https://ollama.com) (`ollama serve`, then `ollama pull llama3.1` or
   `qwen2.5-coder`/`gemma2`/`mistral`) or [Open WebUI](https://openwebui.com) pointed at a local
   Ollama/llama.cpp backend.
2. **CORS**: browsers block cross-origin requests by default, so the local server must explicitly
   allow this app's origin.
   - Ollama: start it with the `OLLAMA_ORIGINS` environment variable set (e.g. `OLLAMA_ORIGINS=*`
     for a trusted local/lab network, or your exact app origin for anything stricter).
   - Open WebUI: enable CORS / allowed origins in its admin settings, or serve this app from the
     same origin as Open WebUI (reverse proxy) to avoid cross-origin requests entirely.
3. Open **Local AI Config** from the ⚙ Settings menu in the top bar, set the Base API URL (and
   bearer token if your server requires one), and click **Test Connection & Fetch Models** — this
   populates the model dropdown and flips the status badge to "Local AI: Connected · \<model\>".
   The page has a built-in CORS troubleshooting box if this step fails.
4. Tune Temperature / Top P / Max Tokens / System Prompt preset as needed, then use the **AI
   Detection Assistant** tab (Gap Analysis / Rule Generator / Explain & FP Analysis).

All AI settings (endpoint, key, model, parameters) persist to `localStorage`
(`sysmon-ai-config::v1`), the same mechanism the rest of the app uses, so the connection survives
reloads with zero server-side session needed — important on an air-gapped machine. If the local AI
server is offline or unreachable, the badge shows "Local AI: Offline" and the AI Detection
Assistant tab shows a notice pointing back to this setup; every non-AI feature (diffing, injection,
exporting) continues to work normally regardless of AI connection state.

## Testing

`tests/` holds a small, dependency-free unit test harness for the app's pure logic modules
(parser, serializer, diff engine, risk analyzer, sanitizer, validator, rule ops, merge engine) - the kind of
code where a regression is easy to miss by eye but easy to assert on precisely. No test
framework: `tests/run.js` defines its own tiny `test()`/`assert()` and runs as a real ES module in
the browser (same import-map mechanism as the app itself, so it needs the same static server).

```bash
cd sysmon-config-manager
python -m http.server 5173
# then open http://localhost:5173/tests/index.html
```

Results render on the page and are also exposed as `window.__TEST_RESULTS__ = { total, passed,
failed, failures }` for driving with Playwright or similar. This suite caught a real bug during
development: a suppressed rule's XML comment only wrapped its header line, not the rule tag
itself, so "suppressed" rules were silently re-activating on export - exactly the class of
regression that's hard to spot by skimming exported XML but trivial to assert on structurally.

## Known limitations

- MITRE tagging is a best-effort keyword heuristic, not an authoritative mapping — treat
  suggestions as a starting point for an analyst to confirm.
- Export does not byte-for-byte preserve the original file's exact whitespace/tag order; comments
  *are* preserved (reattached to the rule/filter/global-option they most likely document - see
  `requirements/schema-notes.md` for the heuristic), but the surrounding XML is re-emitted clean
  and consistently formatted rather than copied verbatim.
- The "which comment belongs to which line" heuristic is based on whether a comment starts its own
  line vs. trails on the same line as the previous tag; it's very reliable for the two real-world
  styles seen in the bundled samples, but an unusual third style could attach a comment to its
  nearest neighbor rather than the "intended" element.
- Validation is a practical rule-of-thumb checker (known tags/conditions/fields, numeric field
  sanity, schema version recognition) rather than a full XSD-based validator.
- `requirements/vendor-deps.py` uses a regex-based (not a full JS parser) import scanner tuned to
